# Apple mobile navigation candidate — 1.1.0 (27)

## What changed

The approved roadmap is `docs/plans/2026-11-15-apple-client-roadmap.md`.
This candidate implements a touch library/search workflow over existing provider
contracts and the original single queue. It does not replace the particle stage.

- New full-screen library: platform filters, bounded playlist rendering, empty
  states, visible platform connection, file import and persistent local library.
- Playlist detail: actual provider identity, 50-track requests, explicit further
  loading, bounded 50-row DOM pages; page selection survives a stage visit.
- Search: existing multi-provider search contract, pagination and stale-request
  rejection. Search results and playlist tracks are kept independently.
- Mini player: title/artist, available artwork, trial label, play/pause, next;
  title opens the original stage. Returning preserves playlist and scroll.
- Stage retains original lyrics, particles, 3D shelf, DIY and pinch. Library
  navigation doesn't reconstruct WKWebView or create a new audio owner.
- New library suppresses legacy top controls, desktop startup walkthrough and
  duplicate native bar. Native lock-screen state still receives original events.
- Rendering behind the opaque library is capped at 2 fps using the original
  scheduler. No extra render loop; polling is 1 second and skips hidden documents.
  This is a scheduling change, not a measured memory/energy result.

## What remains before claiming stable or roadmap complete

- Real iPhone/iPad safe areas, keyboard, gestures, long sessions and background
  audio. User requested no remote iPad operation; none performed here.
- 30-minute same-device resource baseline including WebContent/GPU; no iPad
  memory or crash improvement is asserted from this desktop fixture.
- Apple Music real library covers and subscription tracks; Qishui VIP full track
  beyond 60 seconds; Spotify real configuration/auth/library/playback destination.
  New navigation does not change those platform capabilities.
- Five first-time testers, wider iPad navigation review and VoiceOver hardware
  checks. Tested viewport geometry does not establish a foldable device's support.
- Widgets and Watch remain separate later releases. No empty targets were added.

No TestFlight or App Store upload is part of this candidate. Build 26 remains a
separate rollback commit, and existing user data is not migrated or discarded.

## Follow-up: build 29 — playback exit and native metadata

- Library is a plain dark list with stage-consistent glass accents, no green hero
  or slogan. A fixed, text-labelled Return to Playback action appears in the
  header on every browser subpage, including empty/new libraries; closing no
  longer requires knowing the mini-player title is a navigation button.
- Native controls previously had no provider in their state contract. The web
  bridge now forwards it and SwiftUI displays an Apple Music source badge.
- The native artwork resolver can now read the exact library song's Apple Music
  API representation (include=catalog,albums) with MusicDataRequest's SDK-managed
  authorization, expanding only that resource's Apple CDN artwork template. A
  pure Swift regression rejects unrelated artist art and deceptive hosts.
- Important lyrics bug: tickLyricsParticles consulted the previous HTML audio's
  ended/paused state even during native protected playback. Native lyrics now
  use a separate media state/clock. Late cover revisions no longer increment the
  track-switch token or reset/refetch that same song's lyrics.
- An anonymous real NeteaseNativeAPI probe found the 197866ms Beautiful People
  (feat. Khalid), Ed Sheeran / Khalid recording and a nonempty lyric response.
  No personal account was used and no full lyrics are included in this repo.
- 91 Apple adapter tests and 228 shared tests pass; native metadata parser test,
  project quick check and signed iOS Release build pass. WebKit QA checks seven
  sizes, persistent custom playlists, explicit exit, local WAV and mini pause,
  image ingestion and the full matched-lyric pipeline. Those UI fixtures supply
  synthetic art/lyric lines; they are not a live MusicKit account acceptance run.
- Read-only device information confirmed the connected iPhone 14 Pro has build

## Build 30: Apple artwork and landscape DIY

The attached iPhone 14 Pro reported build 29 and a final native artwork miss
(stage 2, success 0). This locates a failure before JPEG delivery; it does not
identify which MusicKit metadata field was absent. No library or account data
were copied into the repository.

The resolver now checks the playing queue entry, keeps verified MediaPlayer
store IDs separate from numeric device-library identifiers, and can retrieve
Apple artwork by exact catalog ID. A final MusicKit search for the active track
requires matching title, artist, album and duration and an unambiguous result.
The native thumbnail can also use MusicKit's ArtworkImage directly when no
JPEG has arrived. Lyrics continue to use the existing labelled recording match.

A live, credential-free CN lookup for Beautiful People (feat. Khalid), store ID
1464549657, passed the production metadata parser and ImageIO decoder: 600 ×
600, 119926 bytes. This verifies the cover exists, not that the user's library
returns that store ID. Account-to-stage verification on build 30 remains open.

The existing DIY button joins the header layout on short landscape viewports.
The native playback menu also opens the visual settings directly. WebKit hit
testing at 852×393, 667×375 and 393×852 hit the button and changed its mode in
all three cases, including rotation back to portrait.
